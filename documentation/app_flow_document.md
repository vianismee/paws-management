# Paws-Management App Flow Document

## Onboarding and Sign-In/Sign-Up
When a new visitor arrives at the application’s root URL, the system checks whether they have an active session. If they do not, the visitor is automatically shown the sign-in page. From there, the visitor has the option to switch to the sign-up page by clicking the link labeled “Create an account.” On the sign-up page, the user enters an email address, a password, and then confirms the password. When they submit the form, the client code calls the `/api/auth` endpoint, which uses Better Auth and Drizzle ORM to create a new user in the PostgreSQL database. Upon successful account creation, the user is redirected to the dashboard.

Existing users can go straight to the sign-in page where they enter their email and password. The form submission again routes to `/api/auth`, and if the credentials match a record in the database, the user is granted a session and taken to the dashboard. If a user ever wants to sign out, they click the “Sign Out” button in the application header, which calls the sign-out API and returns them to the sign-in page.

## Main Dashboard or Home Page
Once authentication is confirmed, the user lands on the dashboard home page. At the top of the page sits a header that shows the current user’s status, a button for toggling between light and dark themes, and the sign-out control. On the left side, a fixed sidebar presents navigation links; currently it leads to the main dashboard view. The rest of the screen is devoted to the dashboard content, where server components can display dynamic data. This dashboard layout remains consistent as the user navigates within the protected area.

## Detailed Feature Flows and Page Transitions
When a user wants to switch themes, they simply click the theme toggle in the header. That updates the `next-themes` provider on the client, instantly changing colors across the entire layout. If the user tries to access any `/dashboard` route without a valid session, middleware intercepts the request and redirects them back to sign-in. After signing in or signing up, a successful authentication action triggers a client-side redirect to the `/dashboard` URL.

Within the dashboard, server components fetch any required data directly from Drizzle ORM using the same database connection that handles authentication. Although this starter kit holds placeholder page content, any additional page follows the same pattern: the user selects a link in the sidebar, the router loads the layout and page component, and the server component fetches or updates data as needed. For example, if a user later adds a profile page, clicking “Profile” in the sidebar would load `/dashboard/profile`, run the server component logic, and render the user’s details.

## Settings and Account Management
Users manage their account mainly through the authentication system and the theme toggle. There is no separate settings page, but the application header always offers the toggle for dark or light mode. To update personal information or change a password, an additional page could be added under `/dashboard/settings`. Returning from such a page to the main dashboard is as simple as clicking a link in the sidebar or header, bringing the user back to the dashboard home.

## Error States and Alternate Paths
If a user enters an incorrect email or password during sign-in, the form displays an error message above or below the input fields explaining that the credentials are invalid. During sign-up, if the email is already registered or the passwords do not match, the form highlights the specific issue. In the event of a network error or server issue, a fallback banner appears at the top of the page asking the user to try again later. When the database is unreachable, the application shows an error page indicating that the service is temporarily unavailable, and it offers a link to retry once the connection returns.

## Conclusion and Overall App Journey
A typical user journey begins with arriving at the app’s URL, signing up or signing in, and then landing on the dashboard. From there, the user can toggle themes and navigate between protected pages that fetch data from the database. If they wish to end their session, they click “Sign Out” and return to the sign-in screen. This flow covers account creation, secure sign-in, the main layout of the dashboard, and graceful handling of errors, providing a clear path from first touch to everyday usage.
